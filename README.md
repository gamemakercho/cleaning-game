# 도서관 청소 게임

모바일 브라우저에서 실행하는 정적 웹 게임입니다. 화면을 드래그해 고양이를 움직이고, 와다다 버튼으로 넓은 범위를 청소하세요.

## 이야기 복귀와 모바일 드래그 — 2026-10-14

B 이상(70% 이상) 클리어 결과에서만 위쪽의 큰 ‘성공! 사서를 따라가자!’ 버튼을 제공합니다. 아래에는 버튼 배경·테두리 없이11px의 작은 ‘다시하기’ 글씨를 둡니다. 글씨만 작게 보이되 모바일 터치 영역은44px 높이로 유지합니다. 실패 결과는 다시 도전만 가능하며, 성공 결과가 뜨는 것만으로 이야기를 넘기지 않습니다. 재도전은 게임 안에서 다시 시작합니다.

cat-librarian의 iframe으로 열면 호스트가 URL에 storyBridge=1·storyOrigin·storySession·storyGameId를 전달합니다. story-bridge.js는 성공 결과의 복귀 버튼에서만 cat-librarian:minigame-return(version1) 메시지를 정확한 호스트 origin으로 보냅니다. 호스트가 세션·게임·iframe·origin·클리어 결과를 확인해 다음 이야기를 엽니다. 다른 미니게임도 성공 버튼에 이 계약을 연결할 수 있습니다. 단독으로 열었을 때는 CONFIG.next_step_url 또는 CONFIG.story_return_url로 이동하며 호스트의 코스 완료를 기록하지 않습니다.

카카오톡 안의 브라우저에서 게임 드래그가 문서 스크롤로 이어지지 않도록 html/body를 고정하고 overscroll을 차단합니다. 진입 시 화면 높이를 유지하되 실제 공간 축소/회전에는 맞춥니다. 긴 결과 창은 내부만 스크롤할 수 있습니다. 브라우저 자체 주소창이나 하단 도구의 표시를 강제하는 기능은 아닙니다.

수정 파일: app.js(결과 버튼·터치·화면 높이),style.css(고정 문서·내부 스크롤·작은 재도전),config.js(단독 복귀 URL),story-bridge.js(호스트 전달). 기존 엔진의45초·A90%/B70%·청소 판정은 유지했습니다.

브라우저에서 실제 cat-librarian 저장소와 서로 다른 로컬 origin으로 연결해 모바일6조건을 확인했습니다. 통제된100개 자국을 기존 청소 API로69/70/90개 닦아 실제 등급 결과를 검증했으며 손으로 게임을 완주한 것과 구분합니다. 실제 카카오톡/삼성 인터넷 기기와 공개 배포는 미확인입니다. GitHub Desktop에서 이 cleaning-game 저장소를 먼저 Commit/Push한 뒤 cat-librarian 저장소도 Commit/Push해야 새 복귀 방식이 연결됩니다.

## GitHub Pages로 실행하기

1. GitHub에서 Public 저장소를 만들고 README 추가를 선택합니다.
2. Add file → Upload files에서 이 폴더 안의 파일과 assets 폴더를 모두 올립니다. index.html은 저장소 최상위에 있어야 합니다.
3. 커밋을 main 브랜치에 저장합니다.
4. Settings → Pages에서 Source를 Deploy from a branch, Branch를 main, 폴더를 /(root)로 선택하고 Save를 누릅니다.
5. 배포가 완료되면 Pages에 표시되는 Visit site 링크로 접속합니다.

assets 폴더의 이름과 파일 이름을 유지하세요. .nojekyll은 기본 정적 파일 배포를 위한 빈 파일입니다.

## 데이터 사용량

게임이 처음 읽는 이미지와 코드의 파일 크기 합계는 4,598,174바이트(약 4.60MB)입니다. 실제 전송량은 압축, 브라우저 캐시, HTTP 부가 정보에 따라 달라집니다.

화면 이동, 애니메이션, 점수 계산, 다시 플레이는 브라우저에서 처리합니다. 같은 페이지에서 재시작할 때 게임 서버에 추가 데이터를 요청하지 않습니다. 다시 접속하거나 새로고침할 때의 전송량은 캐시 상태에 따라 달라집니다.

별도의 설치, 데이터베이스, API 키가 필요하지 않습니다.

## 이미지 최적화

게임과 스프라이트 미리보기는 WebP 파일을 읽습니다. 캐릭터와 효과 5개 시트는 무손실이며 원본 PNG와 복원 픽셀이 동일합니다. 배경은 해상도를 유지한 WebP 품질 92로 압축했습니다. 프레임 영역, 기준점, 충돌 좌표는 그대로입니다.

원본 PNG는 편집과 복원을 위해 assets 폴더에 보존되어 있지만, 게임이 플레이할 때 다운로드하지 않습니다. 저장소 전체의 파일 크기와 첫 접속 전송량은 다릅니다.
